Понедельник (30 мин)
Задача: Создание структуры ядра

Создать папку core/ в корне проекта
Создать базовую структуру папок внутри:
core/
├── interfaces/
├── services/
├── models/
└── __init__.py

Создать базовый __init__.py в папке core/
Критерий успеха: структура папок создана, проект запускается без ошибок
Вторник (30 мин)
Задача: Перенос логики тренировок (часть 1)

Создать файл core/services/workouts.py
Перенести базовые функции из tg_bot/utils/trener.py:
generate_triple()
generate_short_split()
Убрать все зависимости от Telegram и aiogram
Критерий успеха: функции работают в изоляции, можно импортировать их в тесты
Среда (30 мин)
Задача: Перенос логики тренировок (часть 2)

Дополнить core/services/workouts.py следующими функциями из tg_bot/utils/trener.py:
award_user()
save_approach()
is_good_level()
Создать простой unit-тест для одной из функций
Критерий успеха: одна функция покрыта тестом, все функции работают без Telegram
Четверг (30 мин)
Задача: Перенос расчета календаря жизни

Создать файл core/services/life_calendar.py
Перенести функции из tg_bot/utils/life_calendar.py:
generate_text_calendar()
generate_image_calendar() (убрать зависимости от PIL и сохранения файлов)
Критерий успеха: расчет календаря работает без Telegram-зависимостей
Пятница (30 мин)
Задача: Создание интерфейсов и первое интеграционное тестирование

Создать базовые интерфейсы в core/interfaces/:
user_repository.py (для работы с пользователями)
workout_repository.py (для работы с тренировками)
Написать простой интеграционный тест, который использует функции из core/services/workouts.py
Критерий успеха: тест проходит, можно импортировать core в отдельный тестовый файл
Суббота (30 мин) - опционально
Задача: Анализ и планирование следующей недели

Проверить, какие зависимости остались в перенесенном коде
Составить конкретный план на следующую неделю
Зафиксировать технический долг, который появился при переносе
Критерий успеха: четкий план на следующую неделю и понимание оставшейся работы
Ключевые принципы выполнения:
30 минут без перерыва - только запланированная задача
Коммит после каждого дня - даже если работа не завершена
Простота важнее совершенства - в первую очередь сделать работающий код
Интеграционные тесты > unit-тесты - проверять работоспособность ядра в изоляции
После первой недели у вас будет основа ядра с частью бизнес-логики, полностью отвязанной от Telegram, и вы сможете постепенно переносить остальной функционал.
